# SabtBrooker — چک‌لیست ممیزی امنیتی و تست نفوذ

این سند برای پیگیری وضعیت امنیت لایه‌های مختلف سامانه کارگزاری ایجاد شده است.

## ۱. لایه API (Backend)
- [ ] **احراز هویت (Auth)**:
    - [ ] تست Brute-force روی ارسال OTP.
    - [ ] بررسی انقضای صحیح Access Token و Refresh Token.
    - [ ] تست JWT Rotation و اطمینان از ابطال توکن‌های قبلی.
- [x] **دسترسی (Authorization)**:
    - [x] تست IDOR روی پرونده‌ها (آیا کاربر A می‌تواند پرونده کاربر B را ببیند؟) -> **اصلاح شد در تیر ۱۴۰۵**.
    - [x] تست IDOR روی شروع پرداخت (آیا هر کسی می‌تواند برای پرونده دیگران لینک پرداخت بسازد؟) -> **اصلاح شد در تیر ۱۴۰۵**.
    - [ ] تست RBAC (آیا نقش کارشناس می‌تواند به تنظیمات ادمین دسترسی داشته باشد؟).

## ۲. لایه پرداخت (Payment)
- [x] **دستکاری مبلغ**: آیا می‌توان با تغییر پارامترهای ارسالی به درگاه، مبلغ را صفر کرد؟ -> **امن** (مبلغ در سمت سرور از جدول تعرفه‌ها استخراج می‌شود).
- [x] **تایید تراکنش**: بررسی صحت منطق `VerifyPayment` -> **امن** (مبلغ در زمان وریفای با دیتابیس مطابقت داده می‌شود).
- [ ] **Callback Security**: اطمینان از اینکه فقط IPهای PSP مجاز به فراخوانی Callback هستند.

## ۴. یافته‌های جاری
- **VULN-001 (High)**: آسیب‌پذیری IDOR در هندلر پرونده‌ها.
    - **وضعیت**: رفع شد.
- **VULN-002 (Medium)**: آسیب‌پذیری IDOR در ایجاد لینک پرداخت. امکان صدور فاکتور برای پرونده دیگران وجود داشت.
    - **وضعیت**: رفع شد (Access Control added to InitiatePayment).
